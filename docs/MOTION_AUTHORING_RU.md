# Мастерская движений · эксперимент поверх Lab 1.0 RC1

База ветки `experiment/lab-motion-authoring` — интеграционная сборка `82814f808332c1bed2b9ca65b047fb4fd9a69a56`. Запуск из главного меню клавишей **M**. Для объёмного тела нужен тот же PixelFXBodyRaster, что для H (сборка в [LAB_100_RU.md](LAB_100_RU.md)). U открывает прежний редактор клипов. Основной тестовый риг — 069 C.

## От рисунка к исполнению

1. В M выбрать sprint и нажать «Полёт / акцент». Бег использует принятую форму 090 C и его календарь дистанции. На экране круги отмечают игровые точки. Потянуть ближайшую кисть, локоть или свободное колено; стопа редактируется за носок. Крест показывает желаемую точку. Расстояние Δ измерено от фактически достигнутой точки. У перекрывающихся меток можно заранее выбрать сустав в списке.
2. У цели настраиваются сила, приоритет и ширина фазового окна. На бегу центр сохраняется в фазе переноса одноимённой ноги, если она свободна, или в фазе полного цикла. Смена скорости сохраняет привязку к шагу. В фазе опоры носок заблокирован. Кисть за пределом досягаемости останавливается на границе двух костей. Причина показывается в строке тика.
3. «+ Новая цель» в списке начинает независимую поправку. Выбор сохранённой цели позволяет переместить её при новом перетаскивании. Копировать/вставлять можно между движениями, ⇄ создаёт цель с другой стороны в координатах того же вида сбоку. Парная цель переносится на другую фазу шага. Пропорции правой и левой проекций могут потребовать ручной поправки.
4. Для джеба «Полёт / акцент» переходит к активному маркеру. Перетаскивание меняет геометрию удара. Сам момент контакта можно перенести отдельно, потянув треугольник на шкале U, переиспользованной в M. Ромб перемещает внутреннюю ключевую позу; соседние ключи задают предел перестановки. «Записать позу» обновляет или добавляет ключ; «± Контакт» добавляет или убирает событие выбранной кисти/стопы. Изменение длительности масштабирует и ключи, и события. Тик исполнения остаётся фиксированным.
5. «Новое из текущего» создаёт документ с отдельным id. «Сохранить» заменяет соответствующий JSON через временный файл в `user://motion_authoring/`. «Загрузить» восстанавливает сохранённую редакцию. Один drag отменяется одним нажатием «Отмена». При переключении на другой документ несохранённые изменения теряются. Перед переключением сохранить нужную версию.
6. Выйти в меню и открыть **H**. В списке режимов появится «Мастерская · имя». У выбранной авторской атаки F запускает сохранённое движение, G/K доступны для прерывания. У профиля локомоции кнопка «Бег» использует сохранённую скорость. Ткань B/C остаётся в представлении. В M и H работают `Asset.ensemble` и один `hybrid091/kernel.gd`. Для автономного потребителя API принимает документ локомоции, массив действий и фиксированную частоту 60 или 120.

## Формат v1

Примеры для копирования — `godot/lab/authoring/motions/`. Загрузчик проверяет типы, диапазоны, имена суставов, порядок ключей и версию. Сообщение при ошибке приходит из `Asset.problem`. `build` компилирует изменившийся документ до симуляции. Редактор повторяет последовательность команд для выбранного тика. Обычное воспроизведение использует уже скомпилированные данные.

| Поле | Семантика |
|---|---|
| version, id, name, kind | Версия 1, стабильный id, подпись, gait или action |
| gait: speed, arm_sweep, flight_width | Целевая скорость в единицах 091 за 1/60 с (1–1.85); направление отведённого плеча при спринте (70–115°); ширина поправки полётной дуги (2–7 ед.). Значения контроля 1.85 / 94 / 5. |
| action: duration, keys | Секунды, строго возрастающие ключи от нуля до duration, одинаковая маска локальных углов в градусах. Короткая линейная интерполяция между ключами; время ключей определяет ускорение и акценты. До начала симуляции семплируется через sampler Lab. |
| action: events | Маркеры t, kind=strike, anchor=hand_near/far или foot_near/far. Сохраняется порядок документа. Применение только у активного экземпляра, на round(t × Hz), после окончательного FK. |
| action: release | Необязательный объект по стороне near/far. Четыре возрастающие нормализованные фазы 0…1 задают освобождение, полную власть авторской ноги, начало возврата и восстановление. Нужны thigh, knee и foot_pitch соответствующей стороны в ключах. Компилятор вычисляет траекторию носка тем же FK и решателем 091. В UI редактируются цели; сами четыре границы в этом прототипе задаются в JSON. |
| goals | До 64 локальных целей. joint — hand/elbow/knee/foot + near/far. xy — абсолютная точка в координатах рига, X вправо, Y вниз, в единицах Lab, без смещения по арене. |
| clock, center, width | Центр 0…1 и радиус .01…1. cycle — период полного шага с переходом через ноль; swing_near/far — свободный перенос конкретной ноги, вне переноса отключена; action — нормализованное время действия. У цели плавный колокол 1 − smoothstep от расстояния до центра. |
| weight, priority | Вес 0…1 и приоритет 0…9. На одной цепи выигрывает активная цель большего приоритета, при равенстве — первая в документе. Резкая смена приоритета перекрывающихся целей может дать акцент: при необходимости разнести окна или согласовать цели. |

Задача решается на трёх уровнях: разреженные углы задают хореографию, цель в окне управляет конечностью, опора и ограничения рига определяют результат. Цель колена перенаправляет свободную двухзвенную цепь вокруг тазобедренного сустава, после чего общий решатель проверяет опору и ограничения. Кисть использует существующий `aim_arm`, сохраняющий ветвь сгиба и длины; мягкая цель ограничивает сгиб локтя 170°. Для свободного носка меняется цель нижней IK до решения. У границы опоры влияние гасится. Для опорной стопы приоритет цели не снимает блокировку. Конечную точку могут дополнительно сместить реакция, подъём/опускание корня и незавершённый переход.

Цели сгруппированы по действиям; при замене команды выбирается новая программа. Прежняя поза служит входом инерционного перехода. Снимок авторского режима содержит подпись набора редактируемых данных; разные редакции нельзя смешивать в одном replay. Для межмашинного матча также требуется одинаковая сборка, риг и базовый банк. Ткань, редактор, растеризатор и каденция GIF не входят в состояние.

## Сравнение и проверка

| Пример | Авторская работа и результат |

| Бег | 0 временных ключей, три параметра профиля и локальные поправки. Пример в GIF меняет кисть одной целью за одно перетаскивание. Дополнительные кадры цикла вручную не создаются. |
| Джеб | Из исходного комбо 052a2 B (77 ключей) взят **отрезок 0–31**, всего 32 исходных позы. Сохранены концы, подготовка 14, контакт 20, акцент 22. Добавлялись точки наибольшего отклонения от линейного участка до допуска 4°. Получено 19 ключей. Максимальная ошибка угла 3.556°, расхождение ближней кисти до 0.475 ед.; на тике контакта 0. Для подгонки удара потребовалась одна фазовая цель. |
| Финт | Четыре позы корпуса и одной руки, без события урона и специального контроллера. Цели, маркеры и темп редактируются теми же средствами. |

Локальный профиль Godot 4.7.2/Linux x86-64: полный шаг 60 Гц одного персонажа, включая контактные точки, без рендера. 14 прогонов после прогрева по 80 тиков, p95 исходного джеба 105 мкс, разреженного 104 мкс, с активируемой целью кисти 187 мкс. Сокращение ключей экономит время автора. На игровом тике обе версии уже скомпилированы. Цена поправки в основном связана с FK и IK. Это не замер FPS полной игры.

Тесты на 60 и 120 Гц проверяют опору, ограничения колена/стопы, достижимость кисти, победителя конфликтующих целей и результат контакта. Для изменённой мишени исходный джеб проходит мимо, исправленный снимает 5 здоровья на исходном маркере. Проверяются restore и замена джеба финтом до маркера. Нативный захват отправляет события мыши в обработчик реального редактора, сохраняет и загружает его копию, проверяет равенство снимка на выбранном тике, сравнивает с исходной дорожкой. Отдельный UI-тест отправляет события через сам Viewport. Исходная трасса 091 сохраняется при отключённых целях.

GIF показывает результат редактора в нативном рендере, сверху наложены подписи для сравнения. Обычный просмотр — 30 показанных кадров/с из симуляции 60 Гц, замедленный — все 60 поз за две секунды. Тест сравнения финта показывает одинаковые дорожки намеренно.

## Границы прототипа

Формат покрывает одну принятую модель локомоции, ключевые действия, кисти, локти, свободные колени и носки. Он не решает произвольную акробатику, движение корня в воздухе, падения или ограничение всей поверхности тела. Редактирование траектории в глубину в v1 отсутствует. Выбор clock, импорт произвольного внешнего JSON и переименование документов пока доступны через файлы. Тормозной путь взят из 091. Изменения при большом числе ключей и целей следует профилировать отдельно. Приёмка редактора и новых движений художником открыта.

## Рабочее пространство RC2 — обновление интерфейса
Один режим редактирования. Слева список движений и редактируемых точек; в центре нативное тело с переключаемыми точками и масштабом; справа вкладки Движение, Цели, Ключ. Снизу общая кадровая шкала с дорожками поз, контактов и фазовых целей действия, транспортом и скоростью просмотра. Для бега цели остаются относительными к фазам шага, поэтому не отображаются как ложные временные ключи. Ключи и контакты можно перемещать; вкладка Ключ изменяет угол канала существующей ключевой позы, не подменяя итог IK. Удаление внутреннего ключа сохраняет граничные позы. При смене движения/загрузке несохранённые правки требуют подтверждения. Старый U оставлен для старых клипов и VFX, но всегда показывает расширенные параметры, независимо от сохранённых настроек. Формат v1, Astra, Box2D и боевой runtime не изменены. График кривых, произвольная иерархия костей и редактирование фаз освобождения ноги не включены в эту итерацию.

## Единый процесс авторинга
M — основной редактор формата v1. U — сохранённый старый редактор банка creature_clips.json (другой риг/формат, root XY, VFX и старые события). Никакого автоматического импорта U → M пока нет: нельзя обещать эквивалентность при переносе. Новое действие создаётся в M из текущей позы с начальным и конечным ключами и каналами корпуса/рук/таза, затем редактируются ключи, цели, контакт. Опора остаётся процедурной, произвольный root и независимые ноги требуют расширения формата. Onion Skin показывает реальные исполненные соседние позы ±4 кадра в локальном виде; отдельная симуляция не меняет текущую, отключается при пуске. График показывает исходные углы выбранного канала, клик выбирает ключ, изменение через числовое поле; это не Bezier-редактор и не график конечного IK. Undo/Redo до 100 операций, один drag — одна операция. CI проверяет новые действия, запись/загрузку, угол, Undo/Redo и неизменность симуляции при onion skin.

Панель слева переключается между целями IK и группами доступных каналов позы (корпус, ближние и дальние конечности). График поддерживает вертикальное перетаскивание угла существующего ключа с одним Undo, перемещение времени остаётся в Dope Sheet. Это график ключевых значений с текущей линейной интерполяцией, не редактор произвольных Bezier-кривых. Иерархия групп не заменяет реальную топологию скелета; формат v1 не расширялся.

### Референсы и авторские ноги
Вкладка «Реф.» загружает локальное PNG/JPG/WebP как отдельный слой под моделью. Масштаб, прозрачность, сдвиг, скрытие и удаление не меняют документ или симуляцию; слой не сохраняется в JSON. Вкладка «Движение» для ключевых действий показывает опору: выбрать ближнюю/дальнюю ногу, задать четыре строго возрастающих процента (начало освобождения, полное авторское управление, начало возврата, восстановление опоры), применить. Для отсутствующих углов берутся текущие исполненные позы в моменты исходных ключей; существующие углы сохраняются. Это уже поддерживаемый v1 release, не новый физический режим. Вернуть опору можно без удаления каналов ноги, Undo/Redo работают. Произвольная трансляция корня, VFX-маркеры и автоматический импорт U пока отсутствуют.

### Прямое редактирование позы
Внизу вида модели переключатель «Цели / IK», «Поза / FK», «Исполнение» (1/2/3). IK оставляет прежнее перетаскивание целей. FK для ключевого действия показывает исходные углы поверх текущей базовой позы, без применения к ним перехода, IK и реакции. Потяни линию доступной кости вокруг её центра; Shift округляет угол до 5°. Во время жеста документ и симуляция не меняются, при отпускании записывается угол в существующий или новый ключ. Остальные углы нового ключа берутся из исходной интерполяции, не из результата IK. Один жест — один Undo. Esc отменяет незавершённое вращение. Ноги доступны при наличии окна release и каналов; разворот плеч/таза остаётся числовым параметром. 3 показывает фактическое исполнение Astra; пуск из FK автоматически переключает в исполнение. Это отдельное представление редактора, не новый runtime. Соседние исполненные позы скрываются в FK. Корневое перемещение, произвольная акробатика и импорт старого U не добавлены.
