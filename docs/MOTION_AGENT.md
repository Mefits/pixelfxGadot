# Работа с экспериментальным Lab 0.42

## Быстрый повтор

Из корня архива, в окружении с Python 3, NumPy и Pillow, запусти команду с путём к Godot 4.4.1. Для захвата нужен работающий графический драйвер. Каталог результата должен быть новым.

```sh
python tools/search_motifs.py --godot godot --out review-01
```

Результат содержит исходный и выбранный дубли рядом, на обычной и половинной скорости, машиночитаемый протокол search.json, маски кандидатов и три проверенных SDK-клипа в film/. Готовые результаты этой поставки находятся в results/motifs/. Видеоряд захватывается из viewport движка. GIF собирается из кадров с накопительным округлением длительности до сотых секунды.

## Как задать движение

Файл godot/lab/motion_rd/motifs.json задаёт восемь фаз, рабочую конечность и экранный вектор движения. Строка ключа содержит тик при 60 Гц, X и Y таза, наклон таза и абсолютный наклон корпуса в градусах, затем четыре [x,y] для ближней руки, дальней руки, ближней стопы и дальней стопы. Y растёт вниз, пол проходит через 0. Новый материал удобнее начать с копии подходящего примера. События, слоты и исключение для защитной реакции сейчас задаёт godot/tests/motif_search.gd; при добавлении нового типа движения проверь эту привязку.

Алгоритм сохраняет цели рабочей конечности и ищет изменения таза, корпуса, пассивной руки и контраста подготовки. Сначала он снимает семь вариантов. Вокруг лучшего допустимого варианта выбирает ещё четыре поправки по видимости лица. Решение опирается на три момента (подготовка, акцент, выход) и две изолированные маски акцента. Ошибка опорной стопы проверяется в каждом тике с заданной опорой, ошибка активной конечности проверяется в интервале акцента. Предел обоих отклонений составляет 0,6 пикселя рига. Параметры всех допущенных и отклонённых вариантов сохраняются. Материал для игры — payload.clip выбранной SDK-записи. Проверь подходящий слот и обработку перемещения корня в своей игре.

## Как использовать внешний референс

Пример с записью CMU 13_11 из комплекта:

```sh
python tools/bvh_landmarks.py results/CMU_13_11.bvh --near Left --view travel --out track.json
python tools/reference_motion.py compile track.json --godot godot --plant --pose-threshold 2 --out jump.json
```

Ближнюю сторону и ракурс выбирает постановщик. Для движения на месте задай численный угол вместо travel. Ключи и контакты из записи можно использовать как основу брифа. Разметку намерения и драматических акцентов автоматического BVH-конвертера следует проверить до поиска. Видеовход инициализируется отдельной командой reference_motion.py video; для него нужны модель и дополнительные зависимости, в этой поставке проверен вход BVH.

## Визуальная приёмка

Посмотри клип в обычном темпе, затем сравни подготовку, акцент и выход на половинной скорости. Для восходящего удара проверь просвет у головы. Для подсечки проследи стопу через несколько последовательных кадров и высоту её дуги. Для отшатывания посмотри, воспринимается ли первым движение корпуса. Ранжирование оценивает силуэт и перекрытия в одном ракурсе. Если движение читается как другое действие, сохрани контрпример и исправь бриф. Рост внутреннего балла сам по себе не основание выпускать клип.
