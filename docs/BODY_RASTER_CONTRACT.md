# Body raster interface — v1, Lab 0.54b
Implementation, supported joins, test results and Sol integration: [handoff](BODY_RASTER_HANDOFF_RU.md). Do not change the animation graph or use endpoint IK. The caller owns evaluated positions, part construction and art parameters. Kernel only renders explicit geometry.

## Input
A thin Godot GDExtension class (suggest PixelFXBodyRaster) with a callable render(config: Dictionary, primitives: Array) -> Dictionary; internally use typed C++ structures and contiguous buffers. Astra may choose a faster packed ABI if a simple GDScript wrapper maintains this contract. No dependence on creature joint names or QuickJS in the native kernel.
- Coordinates x right, y DOWN, z towards viewer; orthographic. Units rig px. screen position = origin + XY * density. Same transform for both lanes. Scale/density applies to the geometry, not just display magnification; z/radii remain in common rig units. Explicit origin, width/height, density (e.g. 1,2,3), normalized light vector in same axes (up = negative y). Caller controls image size; test 64/96/128/192 canvas. Do not hardcode mannequin height or clip at floor. A body may be airborne.
- Primitive records: sphere(center xyz,radius); sweep(a xyz,b xyz,ra,rb,bulge); ellipsoid(center xyz, basis 3x3 row-major, radii xyz); each has stable positive part_id, material_id, blend_group (0=no smoothing), optional local frame id. Validate finite numeric inputs and positive radii; normalize/check orthonormal basis; bounded work and dimensions. Stable tie rule (document it). All primitive geometry already in world/rig coordinates. No solving, projection changes, hidden root adjustment, global yaw, or auto-fit. Degenerate zero-length sweep handled predictably.
- Materials: caller-supplied 4-tone packed RGBA ramps, optional single-color flat mode. No fixed armor palette. Outline: off or outside-only, configurable color and integer pixel thickness. Legacy reference seam mode and organic mode: suppress cosmetic lines inside connected parts with same material/blend group; retain genuine front/back occlusion when needed. Keep material boundaries intentional. Do NOT smooth unrelated overlapping arms/legs together.
- Required modes: reference hard depth surface using upstream sweep/sphere/ellipsoid + tone quantization; organic grouped join mode with local controlled smoothing at connected anatomical joins. Removal of lines alone is not geometrical smoothing. If blending is expensive/ambiguous, isolate as second optional pass and report limitations; do not sacrifice reference correctness. Smooth parameter in rig px, zero = reference geometry. Keep depth/normal and part ownership well-defined. No image blur as substitute.
## Output
RGBA8 bytes (row-major, transparent outside), width, height, status/error, optional debug arrays depth, part/material IDs, mask, normals if useful. Ownership/depth must be queryable in tests. Keep stable per-part source coordinate/frame mapping capability as extension point for future body effects; no full UV/texturing required in this pass. No dependency on scene tree; reusable buffers per instance. For Godot integration use Image.create_from_data then update reusable ImageTexture, not per-pixel draw calls in production.
## Tests / acceptance
Reference oracle: derive small primitive-only JS fixture from locked source (copy/extract WITH MIT attribution and provenance outside original/; do not alter submodule). Test upstream sphere/sweep/ellipsoid raster at density 1 including z tie, shade thresholds, isolated-tone cleanup, outline. Compare masks, depth (tolerance stated), material/tone and color separately; use explicit tolerance for float-boundary discrepancies, do not silently relax. Unit tests: crossing two limbs with z swap, equal-z tie, tilted ellipsoid, taper/bulge, clipped canvas edges (no row wrapping), invalid inputs, zero length, outline radius, disconnected crossing must not melt together, connected elbow/knee smooth join, repeated calls and clear/no stale pixels. No effect-specific choreography.
Frozen sample poses: res://tests/fixtures/body_raster/poses.json (18 poses, see manifest); run verifier res://tests/body_fixture_verify.gd. exact 2D x/y preserved; initial z may be supplied by caller as an explicit near/far estimate, do not label as reconstructed 3D. Full exact clips remain in pinned Actions artifacts; no need to recreate motions. Actual Godot captures on same camera/canvas as A, with same pose timestamps, for run, highkick, combo. A current INK51 / B native reference / C organic optional. At minimum 3 contact/overlap poses and run six-phase sheet. No new animation authoring; Sol handles full GIF and art refinement if needed.
Performance: separate CPU raster, bridge, texture upload submission; warmed p50/p95/p99/max for 1/4/8/16 bodies at representative densities, repeat same pose and changing pose separately, count allocations/work; state platform and build flags. 60fps frame budget 16.67ms entire game, not per body; propose p95 <=1ms/body at 64-ish art px on CI as stretch goal, not acceptance claim. No laptop FPS claim. No requirement to port full original actor/IK/catalog. Linux deterministic tests first; Windows build if budget permits; state untested OS. No unrelated full catalog rebuild or repeated Actions.

## 0.55c opt-in extension (Sol, experimental)
`cut_tube(a,b,ra,rb,profile=2,depth_ratio=1)` renders a linearly tapered, flat-ended coplanar tube. Same z at both endpoints; nonzero XY length, positive radii, profile 2..6 (superellipse exponent), depth ratio .1..2. Analytic front depth and normal, shared ownership and z-buffer. Flat end is an XY axial cut, not a general 3D cap renderer. Not eligible for organic sweep joins; use for clothing layered over skin. This is an extension, not upstream parity. Existing sphere/sweep/ellipsoid behavior unchanged.
