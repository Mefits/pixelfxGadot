# N — цель и этапы

Самостоятельный 2D-файтинг на Godot 4.4.1. Два бойца, одна арена. Приоритет: отзывчивость, выразительное движение, вес тела, контакт, импакт и способности. Не воспроизводить чужих персонажей и ассеты. Toolkit — технологическая база, а не часть игрового интерфейса. Проект временно размещён в изолированной ветке project/N, отдельное дерево без файлов Toolkit.

## 0.01 — тело и движение
Детерминированное движение 120 Гц, скорость/ускорение, ходьба/бег, прыжок, опорные ноги с аналитическим двухзвенным IK, явное направление сустава и зеркалирование. Два персонажа, второй пассивный или локально управляемый. Pushbox, без урона и эффектов. Диагностический скин, не финальная графика. Физическая система Toolkit пока не встроена: её fixed-step и разделение позы/рисования использованы как принципы. Новый IK нужен вместо unconstrained CCD для человеческой ноги. Текущий foot planting упрощённый; визуальная приёмка и доводка обязательны.

## Следующие этапы — не начинать всё сразу
1. Приёмка движения: обе стороны, ходьба назад, бег, разворот, старт/стоп, прыжок и посадка, отсутствие скольжения опорной ноги. Не считать тесты доказательством качества.
2. Один прямой удар без VFX: фазы замах/ускорение/контакт/возврат, направление и точный контакт, перенос веса. Сравнение фиксированной реакции и локальной физики. Использовать проверенный XPBD physical_body из Toolkit только после оценки необходимости; сначала импульс корня и ограниченные пружинные углы груди/головы/рук. Не отдавать управление целиком ragdoll. Hitstop не должен влиять на накопление энергии. Отдельно отладить возврат контроля, блок, промах.
3. Ближний бой: лёгкий/тяжёлый, удар ногой, блок, комбо, попадание в воздухе, отбрасывание. Два персонажа должны быть интересны без магии.
4. VFX: использовать зафиксированные оригинальные алгоритмы PixelFX, сравнить с оригинальными кадрами и измерить стоимость. Не подменять оригинал упрощёнными аналогами; статические эффекты можно экспортировать в атлас, динамические — переносить с тестами паритета.
5. Способности: одна электрическая контактная техника (заряд, разгон, шлейф, контакт, восстановление), затем новые только после визуального теста.
6. Художественная оболочка: оригинальные персонажи, модульный скин, волосы/одежда и вторичная физика. Референсы определяет владелец. Звук, камера, игровые правила и баланс по мере необходимости.

Не развивать SDK, редакторы или библиотеку в рамках N. Сохранять данные игрового прототипа и его тесты независимо от Toolkit. Никаких художественных оценок по одному успешному CI.
