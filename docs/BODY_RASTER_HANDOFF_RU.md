# Lab 0.54b · Передача Sol

Ветка `experiment/astra-body-raster-054`, стартовый коммит `8eb0a8c`. Точка входа — GDExtension `PixelFXBodyRaster.render(config, primitives)`. Независимое ядро находится в `native_cpp/body_raster.hpp`. Оно работает с мировыми координатами, не знает имён суставов и не загружает QuickJS. Вся привязка к замороженным позам находится в тестовом скрипте.

## Сборка и воспроизведение

Из корня репозитория, Linux x86-64, C++17, Python, Git, SCons в PATH, Node 18+ и Godot. Сборщик сам получает закреплённый godot-cpp 4.4.1. Для уже используемого в приложении оригинального JS runtime сохраняется прежняя сборка `python native_cpp/build.py --original`. Обычная сборка ниже содержит оба класса растеризации, без JS.

```bash
git submodule update --init original/pixelfx
node native_cpp/body_tests/oracle.mjs
g++ -std=c++17 -O2 -ffp-contract=off -fno-fast-math native_cpp/body_tests/test.cpp -o /tmp/body-test
/tmp/body-test native_cpp/body_tests/oracle.txt
python native_cpp/build.py
godot --headless --editor --path godot --import
godot --headless --path godot --script res://tests/body_fixture_verify.gd
godot --path godot --rendering-method gl_compatibility --audio-driver Dummy --script res://tests/body_raster_smoke.gd
```

Последняя команда требует графический дисплей (можно Xvfb), захватывает три листа из Godot и перезаписывает benchmark.json в [каталоге результатов](body-raster-054/). Для изолированного теста в чистой копии без импорта всего Lab достаточно создать `godot/.godot/extension_list.cfg` с одной строкой `res://addons/pixelfx/pixelfx.gdextension` после сборки. В существующем проекте список расширений ведёт редактор.

## Вызов из Lab

Один экземпляр на независимо рендерящий поток или персонажа. Передавайте окончательные координаты FK. Порядок построения примитивов стабилен. Пример однократной инициализации и обновления:

```gdscript
var raster = ClassDB.instantiate("PixelFXBodyRaster")
var texture: ImageTexture
var config = {"width":96, "height":96, "origin":[40,66], "density":1,
    "light":[-0.48,-0.64,0.6],
    "materials":[[0xffe1d7bf,0xffc0aaa0,0xff957b79,0xff585265]]}

func update_body(primitives: Array) -> void:
    var result: Dictionary = raster.render(config, primitives)
    if not result.ok:
        push_error(result.error)
        return
    var im = Image.create_from_data(result.width,result.height,false,Image.FORMAT_RGBA8,result.rgba)
    if texture == null or texture.get_size() != Vector2(im.get_size()):
        texture = ImageTexture.create_from_image(im)
    else:
        texture.update(im)
```

Назначьте текстуру спрайту с `centered=false` и фильтрацией nearest. При отображении в координатах рига масштаб равен `1/density`, левый верхний угол относительно корня — `-origin/density`. Геометрия и z задаются в одних единицах рига. Экранная сетка берёт пробы в целочисленных координатах, x вправо, y вниз, больший z ближе. Контур задаётся в пикселях целевого изображения.

| Поле | Тип и значение |
|---|---|
| width, height, origin, light, materials | Обязательные. Размеры — целые 1…1024, origin — Array из двух чисел, light — единичный XYZ с допуском 1e-5 по квадрату длины. Materials — Array из 1…256 четырёхцветных Array. |
| Цвет | Целое **0xAABBGGRR** как в PixelFX; четыре тона от света к тени. Для плоской заливки повторить один цвет четыре раза. Для Godot Color собрать число из каналов в этом порядке. |
| density, outline, ink, seams, seam | По умолчанию 1, 1, 0xff000000, true, 0xff303030. Density 0.125…8, outline 0…4 (внешнее манхэттенское кольцо), seams включает внутренние линии независимо от контура. |
| type, part_id, material_id | Обязательные у каждого примитива. Тип — String, part_id — положительный int32, material_id — целый индекс с нуля. |
| sphere | center XYZ, radius. |
| sweep | a, b XYZ, ra, rb и необязательный bulge. Радиус линейно интерполируется плюс bulge × sin(πu). Число интервалов max(2, ceil(length/0.4)); нулевая длина оставляет 3 концентрические пробы. |
| ellipsoid | center, radii XYZ, basis — Array из девяти чисел по строкам, столбцы задают мировые оси эллипсоида. Проверяется ортонормальность. |
| tone_bias, frame_id, blend_group | Необязательные целые. Смещение на 0…3 тона темнее; frame_id по умолчанию −1; группа по умолчанию 0. Векторы и basis передаются обычными Array чисел. |
| debug | При true дополнительно возвращаются плоские массивы depth (float32), part/material/frame (int32), tone (byte). Индекс y × width + x. Маска поверхности — part > 0. Пиксели внешней линии окрашены в rgba и имеют part=0. |
| Результат | ok, width, height, rgba (PackedByteArray RGBA8), cpu_us, body_pixels, sample_tests, field_tests и buffer_growths. При отказе только ok=false и error. |

За один вызов принимаются до 512 примитивов. Центры ограничены ±16384, входные радиусы 0.0001…512. Перед растеризацией проверяются конечность чисел, радиусы и консервативная оценка работ по геометрии (16 млн). При отрицательном bulge проверяется положительность нижней оценки радиуса по всей длине.

**Правило глубины в reference** повторяет plot оригинала. Кандидат в double сравнивается с сохранённым float32. При равенстве сохранённой глубине остаётся первый владелец. Если предыдущая запись округлилась вниз, повторный математически одинаковый кандидат может выиграть сравнение. Порядок первого касания используется также при очистке одиночного тона. Сортировать входные записи между кадрами по нестабильному ключу нельзя. Восстановление source-координат возможно по part/frame, XY пробы и depth при наличии преобразований кадра у вызывающей стороны.

## Органические суставы

Для двух сегментов цепочки укажите одинаковые положительные blend_group и material_id. Передайте `mode="organic"`, `smooth=1.0` (диапазон 0…8 единиц рига) и `joins=[[0,1]]` — упорядоченные индексы примитивов в массиве. Конец первого sweep должен точно совпадать с началом второго. Версия 0.54b поддерживает соединение двух sweep в одной плоскости постоянного z. Остальные примитивы сцены могут свободно менять глубину. Несовместимая заявленная пара возвращает ошибку; для наклонных в глубину сегментов Sol может оставить обычное соединение, исключив пару из joins.

В окрестности сустава каждый сегмент даёт поле максимума r²−dx²−dy² вдоль исходных сфер. Локальный гладкий максимум этих полей меняет глубину и способен расширить силуэт. Ширина смешивания спадает до нуля на расстоянии 2 × min(rb₁,ra₂) + smooth. Освещение вычисляется по производным поверхности. Владелец выбирается по большему исходному полю (первый сегмент при равенстве); итог проходит общий тест глубины. Мягкий шов подавляется между пикселями одной обработанной пары. Порог исходной линии окклюзии 2.2 сохранён. При smooth=0 результат соответствует reference. Само пересечение или общий номер группы сглаживание не запускают.

## Проверки и кадры

- Oracle извлекает действительные функции plot/sphere/sweep/ellipsoid, очистку тонов, швы и построение кольца из неизменённого rig.js (MIT, ревизия 5294518, проверяется SHA-256 файла). На 4 сценах 33×33 проверены все 4356 пикселей. Расхождений по маске, владельцу/материалу, тону и RGBA — 0. Глубина сравнивалась с абсолютным допуском 1e-6, превышений — 0. Спецматериал оружия, отметка на груди, IK и пересчёт rest-frame в oracle не входят.
- C++ тесты включают смену передней конечности, равную глубину, границы порогов тона, наклонный эллипсоид, bulge, нулевую длину, масштаб, границу холста, очистку между вызовами, неверную basis и радиусы, превышение бюджета. Два угла сгиба проверены на появление новых пикселей силуэта, увеличение глубины и локальность изменения. Передний независимый объект сохраняет владение. Проверена сборка с AddressSanitizer и UndefinedBehaviorSanitizer. Для прежнего VFX kernel отдельный тест дал 0 расхождений на 32 исходных сценах.
- Linux x86-64, Godot 4.4.1 и 4.7.2: штатный verifier проверил 18 входов, максимум ошибки XY 0.000004265 единицы. GDExtension smoke проверяет ошибочные входы, массивы результата, все позы и три настоящих захвата Godot. Windows для этой реализации не проверялась.
- На каждом листе сверху вниз идут INK51, C++ reference и C++ organic. Для трёх рядов совпадают камера, XY и tick. На тестовом манекене передняя пара конечностей имеет z=+4, дальняя −4, корпус 0. Это явное допущение теста. На высоком ударе хорошо виден порядок перекрытия ноги и корпуса; при density=1 сглаживание малозаметно. Кисти, обувь, одежда и специальная форма головы относятся к будущему адаптеру Sol.

## Измерения

[benchmark.json](body-raster-054/benchmark.json) содержит 48 комбинаций: два режима × плотности 1/2/3 (64/128/192 px) × 1/4/8/16 независимых экземпляров × повтор/смена позы. После 24 прогревочных циклов измерено 100 последовательных обновлений группы. Времена в микросекундах, порядок в каждом массиве — p50/p95/p99/max (nearest rank). Счётчики работ даны в том же порядке. Отдельно замерены ядро с валидацией, остальная часть вызова вместе с подготовкой Image и CPU submission вызова ImageTexture.update. Total складывается по каждому циклу до расчёта процентилей. Буферы ядра повторно используются; buffer_growths считает события увеличения их ёмкости за измеренную серию. Bridge каждый раз выдаёт новый packed RGBA, в debug ещё пять массивов. Аллокации внутри Godot не инструментировались. Время исполнения команд на GPU и время всего игрового кадра не измерялись.
